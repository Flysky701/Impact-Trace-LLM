# Impact-Trace-LLM

**基于 LLM 与代码知识图谱的软件变更影响平台**

项目源于课程作业，关注阅读项目时难以理解整体架构、难以判断 AI 修改代码的影响这两个问题。目标是结合代码知识图谱与大语言模型，帮助使用者理解项目结构、回顾 AI 修改过程，并获得有源码依据的变更解释。

计划在一个月以内完成可演示、功能基本可用的原型。首版建议完成“项目结构浏览 → 记录修改任务 → 对比修改前后 → 解释潜在影响”的流程。多语言作为扩展方向，先通过一个开源样例仓库验证主要流程。

当前仓库仅包含项目规划与协作基础配置，尚未实现可运行系统，也未确定编程语言、框架、数据库或模型供应商。

GitHub 公开仓库：[Flysky701/Impact-Trace-LLM](https://github.com/Flysky701/Impact-Trace-LLM)。默认分支：`main`。

## 预期使用流程

1. 接入代码仓库，浏览模块、文件和主要依赖，查看附源码依据的结构说明。
2. 记录一次 AI 修改任务的用户要求与修改前后提交；已有对话或操作记录可人工附加。
3. 解析差异，定位变更实体，生成潜在影响集合和传播路径。
4. 由 LLM 基于代码片段与关系证据解释实际改动、可能影响和需复核的问题。
5. 在报告中查看任务要求、实际改动、源码定位及建议检查项。

## 本地开始

打开本仓库，先阅读项目定位与需求草案。当前仅需 Git 和文本编辑器，无需安装业务运行环境。后续确定技术栈后再补充源码目录、依赖管理、运行命令与自动化测试。

在其他目录或机器获取项目：

cd Impact-Trace-LLM
