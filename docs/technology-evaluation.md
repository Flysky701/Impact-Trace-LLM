# 技术选型计划

状态：已形成 [ADR-0001](adr/0001-mvp-technology.md) 实施基线。FastAPI、Vue/TypeScript、SQLite/SQLAlchemy 已完成仓库浏览骨架集成，依赖已锁定。AST 与基础关系查询已初步验证；正式解析、Cytoscape.js 影响图及模型连接待实现。本文保留评估方法与复评条件。

## 课程原型的取舍

已确认由 1 人开发、交付时间为一个月以内，优先选用容易集成和演示的方案。建议用两到三天完成小样例验证并形成初步决策，遇到方案阻塞及时缩小支持范围。无需把本文件列出的所有实验做成完整研究评测后才开始实现。

- 已选定 Python/TinyDB，固定快照和历史案例见[样例验证](sample-validation.md)。
- 解析器保留多语言接口，首批只要求一种语言的主要流程可用。
- 展示需同时支持结构理解、修改记录和影响解释。
- 重点人工检查少量案例中的实体、关系、源码定位和解释依据，保留必要的失败处理。
- Web 界面、开发者与审核者的必要权限、审核记录和历史查看进入首版；前后端自有业务源码行覆盖率分别须达到 ≥75%，详见[测试方案](testing-plan.md)。
- 存储、任务执行及部署优先保持简单；只有样例需要时才增加组件。

## 外部模型意味着什么

使用云端模型时，应用通过 API 将选定的代码片段、diff、依赖摘要或用户问题发送给模型服务商，再接收分析结果。具体发送哪些内容由应用设计决定，不必上传整个仓库。数据保留和使用方式依赖所选服务与账户设置，需在选定后核实。

本地模型在本机执行推理，可避免为推理向云端发送源码，但需要匹配模型的硬件资源与部署工作。是否允许源码外发不会自动决定 GitHub 仓库是否公开，两者是不同的数据流。

用户将模型服务候选限定为 DeepSeek 或 OpenAI，并提出 OpenAI 使用 OAuth 授权。仅发送公开开源样例的相关源码片段。具体模型、费用预算及实际调用能力仍待确认；仓库内的凭据等敏感信息不进入请求。若后续使用未公开代码，再单独明确处理方式。

### 模型服务与认证候选（2026-10-02 核对）

- DeepSeek：官方文档使用 API Key 进行 Bearer 认证；尚未确认可用于本项目的官方 OAuth 模型调用方案。参考：[DeepSeek API 文档](https://api-docs.deepseek.com/)。
- OpenAI：用户希望采用 OAuth。官方 Sign in with ChatGPT 文档提供面向开源、本地运行应用的授权方案，符合条件的用户可以授权应用使用 ChatGPT 计划执行允许的 Responses API 请求。身份登录权限与模型调用权限不同，需申请相应调用权限，完成账号资格与实际请求验证；不能仅凭已登录 ChatGPT 就认定模型接入成功。参考：[Quickstart](https://developers.openai.com/siwc/quickstart)、[开源应用接入说明](https://developers.openai.com/siwc/token-sharing-open-source)。
- 本项目的开发者／审核者权限仍由平台管理，模型服务授权单独处理。当前仅记录候选与用户偏好，尚未进行认证、发送源码或产生付费调用。

## 先明确约束

在选型前确认目标代码语言、样例仓库规模、团队经验、交付时间、运行资源、源码外发规则及成本预算。候选产品的版本、授权、价格和维护状态在实际评估时查询官方资料并记录日期。

## 验证实验

### 实验 A：解析与影响传播

使用包含调用链、循环依赖、重命名和实体删除的同一组样例。先人工标注实体、关系和预期影响，再测量提取准确性、影响遗漏、误报及耗时。语法树提取与符号解析能力分别记录。

### 实验 B：LLM 带来的收益

比较“仅依赖图分析”和“依赖图分析加 LLM 解释”。使用相同变更和证据，评价解释是否正确、是否能追溯、测试建议是否有用，并记录模型配置、模板版本、调用次数和费用估算。重复部分样例以观察输出波动。

### 实验 C：存储与版本一致性

在相同数据上验证两个提交的隔离、删除实体的历史关系查询、反向依赖检索和循环处理。记录导入时间、查询时间、存储大小和运行环境，再判断是否需要专门的图数据库。

## 评价与决策

1. 先检查必须满足的约束，淘汰无法满足授权、数据处理或功能要求的候选方案。
2. 对余下方案比较正确性、性能、成本、维护难度和团队熟悉度；权重在评估前确定。
3. 课程首版记录少量案例的正确与错误结果、证据能否定位、运行时间和模型用量即可。若进一步报告精确率或召回率，应有人工标注；无标注或分母为零时标为不适用并说明原因。
4. 明确人工标注边界和样例局限；小样例验证不能直接代表大型真实仓库的表现。
5. 将结论、替代方案、限制和复评条件写入 ADR，再建立对应代码与依赖配置。
