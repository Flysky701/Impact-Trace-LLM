# 技术选型计划

状态：尚未选型。本文定义评估方法，不指定产品、框架或版本。

## 先明确约束

在选型前确认目标代码语言、样例仓库规模、团队经验、交付时间、运行资源、源码外发规则及成本预算。候选产品的版本、授权、价格和维护状态在实际评估时查询官方资料并记录日期。

## 评估矩阵

| 方向 | 需要验证的能力 | 实验产物 |
| --- | --- | --- |
| 实现语言与后端框架 | 团队开发效率、解析工具集成、异步任务与错误处理 | 最小任务接口及开发成本记录 |
| 代码解析方案 | 语法覆盖、符号解析、调用目标、源码定位、容错 | 同一组代码样例的实体和关系对比 |
| 图谱存储 | 版本隔离、反向依赖查询、路径检索、批量导入、部署成本 | 同一数据集的查询结果与资源记录 |
| LLM 接入 | 数据边界、上下文限制、引用质量、失败处理、成本 | 固定证据集上的解释结果与评分 |
| 展示方案 | 影响列表、路径交互、源码定位与大结果集浏览 | 单份报告的可交互原型 |
| 任务与部署 | 本机可复现、状态恢复、诊断、资源限制 | 从请求到结果的最小运行链路 |

若需要语义检索，再单独评估向量检索；是否引入该组件以已确认的使用场景为依据。

## 验证实验

### 实验 A：解析与影响传播

使用包含调用链、循环依赖、重命名和实体删除的同一组样例。先人工标注实体、关系和预期影响，再测量提取准确性、影响遗漏、误报及耗时。语法树提取与符号解析能力分别记录。

### 实验 B：LLM 带来的收益

比较“仅依赖图分析”和“依赖图分析加 LLM 解释”。使用相同变更和证据，评价解释是否正确、是否能追溯、测试建议是否有用，并记录模型配置、模板版本、调用次数和费用估算。重复部分样例以观察输出波动。

### 实验 C：存储与版本一致性

在相同数据上验证两个提交的隔离、删除实体的历史关系查询、反向依赖检索和循环处理。记录导入时间、查询时间、存储大小和运行环境，再判断是否需要专门的图数据库。

## 评价与决策

1. 先检查必须满足的约束，淘汰无法满足授权、数据处理或功能要求的候选方案。
2. 对余下方案比较正确性、性能、成本、维护难度和团队熟悉度；权重在评估前确定。
3. 指标至少包含影响集合的精确率与召回率、有效证据引用比例、端到端耗时和单任务成本；无标注或分母为零时标为不适用并说明原因。
4. 明确人工标注边界和样例局限；小样例验证不能直接代表大型真实仓库的表现。
5. 将结论、替代方案、限制和复评条件写入 ADR，再建立对应代码与依赖配置。
