# 首版实施方案

日期：2026-10-02。状态：根据用户授权形成的实施基线。当前已完成登录、项目权限、Git 历史与源码浏览的可运行骨架，依赖已锁定并通过相应测试；正式影响分析与模型连接尚未实现。

2026-11-06 补充：本文保留技术基线；当前完成情况以[项目现状](project-status.md)为准，后续实施顺序以[阶段计划](roadmap.md)为准。扩展能力及接口边界见[功能扩展规划](requirements.md#功能扩展规划)。

## 交付目标

由 1 人在一个月以内完成本机 Web 演示：开发者登录并导入仓库，浏览结构，填写一次修改任务，选择两个提交，查看差异、潜在影响及解释；审核者登录确认风险、记录测试结果，随后可以回看历史报告。沿用需求文档中的 F1～F10，不另增功能数量。

## 技术基线

| 部分 | 采用方案 | 选择理由与边界 |
| --- | --- | --- |
| 后端 | Python 3.13、FastAPI、Pydantic | 当前本机已有 Python 3.13；便于接入 Python 解析和接口测试 |
| 首批分析语言 | Python，标准库 ast 加有限的符号解析 | 先提取实体、导入、明确的调用候选；语法树本身不能解决动态调用 |
| Git 读取 | Git 命令行，通过参数数组调用 | 读取提交对象与差异，保留用户工作区；基准与目标版本各自构图 |
| 持久化 | SQLite、SQLAlchemy 2.x | 用户、任务、报告与图节点/边存表；单机、小样例降低部署成本 |
| 影响传播 | Python 邻接表和反向广度优先遍历 | 可保存每条边的来源，控制循环、深度和规模 |
| 界面 | Vue 3、TypeScript、Vite | 登录、项目、任务和报告用同一个 Web 应用组织 |
| 关系图 | Cytoscape.js | 展示节点、依赖边、变更高亮及选中路径；源码使用只读文本视图 |
| 后端测试 | pytest、pytest-cov、FastAPI TestClient | 验证分析、权限、存储与模型失败处理 |
| 前端测试 | Vitest、Vue Test Utils；少量 Playwright 流程测试 | 分别检查交互逻辑与浏览器完整流程 |
| 模型 | 可替换的 DeepSeek API / OpenAI OAuth 适配器 | 首版先打通一种真实连接；另一种保留接口，不作为首版双接入承诺 |

首批语言为 Python，平台界面使用 TypeScript，不表示首版能分析 TypeScript 项目。独立图数据库、多语言、任务队列集群在后续需求触发时再评估。技术依据见 [ADR-0001](adr/0001-mvp-technology.md)。

## 数据与模块安排

建议目录：`backend/app/` 放接口与服务，`backend/tests/` 放测试，`frontend/src/` 放界面，`scripts/` 放复现实验工具。业务目录在开始实现时创建。

- 用户、会话、项目访问：本地账号、标准密码哈希库、服务端会话，Cookie 使用 HttpOnly 和适当 SameSite；写操作校验角色及项目访问范围。演示初始化两个账号，成员邀请后置。
- 仓库与快照：保存本地路径、仓库标识、完整提交 SHA、解析器版本及诊断。图实体以快照和限定名称等组合区分。
- 分析任务：保存基准/目标提交、用户任务、人工附加记录、状态和阶段错误。单工作进程顺序处理，界面轮询；进程中断后将遗留运行任务标为中断，允许重试。
- 图节点与关系：文件、模块、类、函数；包含、导入及能确定的调用。每条关系保存源位置、所属提交和解析状态。继承可展示，传播规则需单独验证。
- 报告与审核：分别保存基础分析和模型解释的状态、证据引用、风险确认、操作者、时间及手动测试结果。修改前后版本和审核记录始终关联同一任务。

首版不推断任意对象类型；对于动态属性、猴子补丁、反射、回调和不明确的调用目标，保存未解析记录。已知同类方法调用也需考虑遮蔽与继承，不能把实验中的语法候选直接当作完整语义解析结果。

## 页面与流程

页面已调整为[产品设计 v0.3](product-design.md)与[仓库审阅原型](prototype/review.html)，采用“代码 / 架构 / 比较 / 检查 / 审阅记录”。下列流程表达业务顺序，实际页面以 v0.3 为准。原型独立于正式应用，不调用分析或模型接口。

1. 登录及项目列表：开发者创建项目，登记本地仓库；审核者查看有权限的项目。
2. 项目概览：选择一个提交，浏览模块/文件及主要关系，点击定位该版本源码。
3. 新建分析：输入任务描述，选择基准/目标提交，附加可选的真实操作记录。
4. 分析报告：展示变化、直接/间接潜在影响、路径、证据、未解析关系和模型解释状态。
5. 审核与历史：审核者记录风险和测试结果，双方回看已有报告。

Git 历史修复不自动标为 AI 修改。演示历史案例时注明“历史提交分析”；AI 修改记录使用有实际任务及前后提交的另一个案例。

## 首版默认限制

以下是可调整的初始配置，不是已测得的性能指标：分析以一个仓库的两个提交为单位；默认传播深度 5，图界面首次展示最多 300 个节点，并提示截断；单个源码文件超过 1 MiB 先跳过并列出原因。读取源码使用 Git 对象，不执行被分析项目的安装、构建或测试脚本。

模型仅接收公开样例中相关的代码片段与证据摘要；记录模型、提示模板版本和用量。超时初始设为 60 秒，临时网络错误最多重试一次，认证/额度错误直接提示。重复打开历史报告不重新调用模型。没有连接或模型失败时可查看静态结果。

具体模型、预算和 OpenAI OAuth 账号资格在真实调用前验证。模型适配器的自动化测试使用模拟响应；模拟结果不作为真实模型效果的证据。

## 一个月内的单人安排

| 周次 | 实施重点 | 完成标准 |
| --- | --- | --- |
| 第 1 周 | 工程骨架、登录双角色、项目/仓库、版本读取、AST 实体与导入关系 | 两个账号权限可验证；样例可读取；源码位置对应固定提交；测试从第一批逻辑开始编写 |
| 第 2 周 | 两版本图谱、变更映射、调用候选与影响路径、基础报告 | 固定历史案例能输出可核对的变化及路径；新增/删除/无变化与循环样例可检查 |
| 第 3 周 | 一种真实模型连接、图谱浏览、任务记录、审核与历史 | 完整 Web 流程可演示；模型失败仍可查看结果；真实调用与模拟测试分别记录 |
| 第 4 周 | 覆盖率补齐、权限与异常检查、复现脚本、课程报告和演示 | 前后端行覆盖率分别 ≥75%；演示可重复；已知局限清晰；本机启动说明完整 |

每周按功能顺序完成后再推进下一项。进度不足时削减图形装饰、文件导出、第二模型/第二语言等扩展，保留 F1～F10 与测试门槛。详细验收见 [测试方案](testing-plan.md)，演示数据见 [样例验证](sample-validation.md)。
