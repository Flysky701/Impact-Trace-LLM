# 项目定位

状态：讨论草案。更新时间：2026-10-02。

## 主题与目标

项目名称：基于 LLM 与代码知识图谱的软件变更影响平台。

希望回答三个问题：一次变更可能影响什么、为什么可能受影响、应优先验证什么。报告应支持用户从结论追溯到变更代码、依赖路径和相关测试。

## 拟解决的问题

- 代码依赖分散在文件与模块中，人工追踪调用方和间接依赖需要时间。
- 单看代码差异难以解释变更在业务语义上的影响。
- 影响分析结果需要可核对的证据，便于评审与回归测试安排。

这些是待验证的需求假设，应通过目标用户访谈或具体变更案例确认优先级。

## 预期用户与产出

| 用户（待确认） | 使用场景 | 预期产出 |
| --- | --- | --- |
| 开发人员 | 修改接口、函数或数据结构后检查影响 | 受影响实体和依赖路径 |
| 代码评审人员 | 审查一次提交的变更范围 | 变更摘要、证据及需要复核的问题 |
| 测试人员 | 安排回归测试 | 有证据支持的测试关联和测试建议 |

## 建议的首版边界

- 先支持一种编程语言和单个仓库。
- 先支持两个明确提交之间的离线分析。
- 先建立可解释的静态分析结果，再验证加入 LLM 的收益。
- 报告表达“潜在影响”，保留解析失败、未解析依赖及模型不可用等状态。
- 多语言跨仓库分析、自动修改代码、自动执行不可信代码、自动合并变更暂放入后续范围。

## 成功的判断方式

以一组可复现的变更样例验证：能够完成分析、能够追溯结论、能够记录遗漏与误报。效果、时间和成本阈值应在需求评审及基线实验后确定。
